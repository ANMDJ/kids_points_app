# 积分小管家 · 微信小程序高保真原型

一个**不装微信开发者工具、双击就能点**的高保真可交互原型。
它是 `kids_points_mp`（Taro 4 + React 小程序）的**视觉与语义替身**：
配色、字号、间距、图标路径、文案派生规则、初始数据全部**照抄仓库**，
所以评审时看到的就是真实产品该有的样子。

```
prototype/
├── index.html      小程序外壳（状态栏 + 胶囊按钮 + 5 页 + 底部导航 + 弹窗层）+ 左侧评审导航
├── styles.css      样式（色值与数值与 kids_points_mp/src/styles/vars.scss 一一对应）
├── app.js          交互逻辑（图标库 / 文案派生 / 状态中心 / 渲染 / 弹窗 / 事件）
├── verify.mjs      自检闸门：在 jsdom 里真跑一遍原型，逐条断言界面上的数字与文案
└── README.md       本文件
```

## 1. 怎么打开

直接双击 `index.html`（Chrome / Edge / Safari 均可，**无需构建、无需本地服务器**）。

左侧面板是**评审工具**（不属于小程序本体），可以：

- **跳转到任意页面**：首页 / 心愿单 / 我的 / 积分记录 / 积分规则
- **直接打开任意弹窗**：记一笔 / 新增心愿 / 新增规则 / 编辑规则 / 规则操作菜单 / 回收站
- **开关显示**：微信胶囊按钮、右下角叶子装饰
- **重置原型状态**：回到 124 分 / 4 条流水的初始态

## 2. 可以点什么

| 页面 | 交互 | 预期表现 |
| --- | --- | --- |
| 首页 | 点习惯卡 | 加分 + 顶部数字变化 + 卡片进入「今日已完成 N 次」 |
| 首页 | 长按习惯卡 | **写入一条冲正流水**（原记录保留），积分扣回 |
| 首页 | 记一笔 | 底部弹窗：奖励/扣分、快选额度、常见事由、补充说明 |
| 心愿单 | 点「兑换」 | 扣分 + 生成「兑换：<完整标题>」流水 + 卡片转「已兑换」 |
| 心愿单 | 长按卡片 | 二次确认 → **软删**到回收站（90 天内可恢复） |
| 心愿单 | 滚到底 | 右下角悬浮按钮从圆形展开成整行胶囊（340ms 补间） |
| 我的 | 点头像 / ID / 回收站 | 改昵称（≤16 字）/ 复制回执 / 回收站弹窗 |
| 积分记录 | 全部·表扬·兑换·调整 | 按天分组（今天 / 昨天）+ 条数实时变化 |
| 积分规则 | 点或长按规则 | 操作菜单：编辑（当前第 N 版）/ 加入今天的习惯 / 移到回收站 |
| 积分规则 | 新增规则 | 频次是**结构字段**（1–5 次/天），勾选图标，扣分方向会拒绝加入习惯 |
| 回收站 | 恢复 / 彻底删除 | 两条路径各一条；恢复回列表，彻底删除需二次确认 |
| 任意弹窗 | Esc / 点遮罩 / 关闭按钮 | 收起 |

> 「每天最多 2 次」的习惯**可以打两次**，第三次会被拦下并告诉你原因 ——
> 这是 `design/03` 的 A2 / A3 修复点，原型里能直接验证。

## 3. 视觉与语义的同源关系（改样式前请看这里）

| 原型里的东西 | 来源 | 说明 |
| --- | --- | --- |
| 画布 `400 × 866` | Flutter 设计稿 400 逻辑宽 | 小程序端 `750rpx` ＝ 屏宽，故 **1 设计 px ＝ 本文件 1px**，Taro 侧的 `f2r(20)` 就是这里的 `20px` |
| `styles.css` 的色板 | `kids_points_mp/src/styles/vars.scss` | `--primary: #b7e28f` 等逐条对应，`--page-top/--page-bottom` 是页面渐变 |
| 每个组件的字号 / 内距 / 圆角 | 各页面与组件的 `.scss` | 注释里标了来源，例如「AppCard padding [14,13] → `13px 14px`」 |
| 图标（`.kp-icon`） | `kids_points_mp/src/components/Icon/icons.ts` | 同一份 24×24 矢量路径，运行时注入颜色（无图片资源） |
| 积分罐 / 叶子装饰 | `PointsJar` / `LeafDecoration` 的 SVG | 原封不动搬成 CSS `background-image` |
| `limitTextOf` / `doneTextOf` / `ruleDetail` / `recordSubtitle` / `amountText` / `dayLabel` | `kids_points_mp/src/data/types.ts` | 逐字照抄 —— **原型里没有一句手写的展示串** |
| 积分 / 习惯 / 心愿 / 流水 / 规则 | `kids_points_mp/src/data/seed.ts` | 124 分 / 324 / 4 / 三条习惯 / 四条心愿 / 四条流水 / 四条规则 |
| 打卡上限、冲正、软删、超额扣分拒绝 | `kids_points_mp/src/data/store.ts` | 连**失败文案**都照抄（例如「今天已经完成 N 次啦，明天继续加油～」） |

已跑通的动作链路：打卡 → 撤销（冲正）→ 记一笔 → 兑换 → 新增/编辑规则 → 加入习惯 → 软删 → 恢复 → 彻底删除。

## 4. 自检（改完请跑）

```bash
node prototype/verify.mjs
```

在 jsdom 里**真跑一遍原型**，逐条断言界面上的数字与文案（11 条用例 `P1`–`P11`）：
打卡上限拦截、冲正而非删除、按天分组、副标题派生、筛选条数、兑换扣分、
软删与恢复、记一笔的事由拼装、新增规则的空标题拦截与「家长约定」兜底，
以及一条**全屏冒烟**（5 个页面 + 6 张弹窗逐个打开、逐个收起，全程不许有未捕获异常）。

- 依赖 `jsdom`：**复用 `kids_points_mp/node_modules` 里已有的那份**，不新增任何依赖。
- 输出 `ALL PASS` 且退出码为 0 才算通过；失败会逐条打印「期望 / 实际」。

## 5. 已知差异与观感说明（不做隐藏）

原型与仓库的差异**只有下面这些**，每一处都写清了是「原型修正」还是「刻意保留」：

1. **编辑规则的版本号提示（原型修正）**：`AddRuleSheet` 的成功提示写的是
   `rule.currentVersion + 1`，而 `updateRule` 已经**原地**把 `currentVersion` 加了 1 ——
   于是会多报一版。原型按语义显示正确的版本号（改动前的版本 + 1），没有复制这处笔误。
2. **「今天」的时间是固定钟点（刻意保留）**：`seed.ts` 把今天的流水钉在 19:30 / 18:50，
   所以你在上午打开时，新打的卡会排在 19:30 那条**下面**（列表按时间倒序，不按写入顺序）。
   这是演示数据的既有口径，不是原型缺陷 —— 保留它是为了和 `design_mockup_0.jpeg` 逐屏对齐。
3. **首页的绿勾只出现在「已达上限」的习惯上（刻意保留）**：设计稿里两张卡都画了绿勾，
   但按 A3 的口径，`checked` 是**派生态**（`今日完成次数 ≥ 每天上限`）。
   演示数据是 番茄钟 1/2、自己收书包 1/1、自主阅读 0/1，所以只有中间那张是绿的。
4. **兑换流水的副标题（刻意保留）**：设计稿只写「已兑换」，原型按 E19 派生为
   「19:10 · 兑换奖励 · 已兑换」—— 备注是**附加段**，不替换真实来源。
5. **复制孩子 ID 只给轻提示（环境限制）**：`file://` 下剪贴板 API 受限，
   原型不写系统剪贴板，只回执「已复制孩子 ID」（小程序里走 `Taro.setClipboardData`）。
6. **回收站初始为空（刻意保留）**：`seed.ts` 的口径是「回收站是用出来的，不预置」。
   想看到回收站的内容，先长按一张心愿卡或一条规则删掉它。
7. **不含尚未落地的能力**：后端接口、审批流、通知、Agent、首次引导页在仓库里都还没有实现
   （见 `docs/PRD.md` §15 与 `docs/design/04`），原型同样**不假装**有。

## 6. 与 `kids_points_mp` 的关系

两者**互不影响**：本目录是纯静态文件，不被 Taro 构建引用，也不进 `dist/`。
它承担的是「评审/演示」职责；真正上架的小程序代码始终是 `kids_points_mp/`。
如果原型里改了一处配色或文案，正确做法是**同步改 `kids_points_mp` 的对应文件**，
再回来对齐这里 —— 而不是只改原型。
