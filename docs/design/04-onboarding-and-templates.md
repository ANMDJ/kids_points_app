# 04 · 首次引导与规则模板库

> **前置确认**：全代码库搜索确认**没有任何引导相关代码** ——
> 无 `onboarding` / `welcome` / `guide` / `tutorial` / `首次` 相关文件或路由。
> 现有应用首启直接进入首页并展示 **seed 假数据**（124 分 / 324 好习惯 / 4 次奖励 / "萌新铲屎官的小可爱"），
> 见 `03` 的 E18。本文档定义从"空态"到"孩子完成第一次打卡"的完整路径。

## 1. 为什么引导是 W0 必须项而非可选项

| 问题 | 现状 | 引导后 |
|---|---|---|
| 新用户看到什么 | **124 分 / 324 好习惯**（别人的假数据） | 0 分空态 + "先定个约定吧" |
| 家长第一动作 | 不知道该做什么 | 3 步选定规则 → 立刻可用 |
| 规则从哪来 | 空白表单手写（`add_rule_sheet` 只有 `规则名称`/`细则`/`积分方向`） | 从模板库一键采纳 |
| "每天最多 2 次"怎么写 | 手打进 `detail` 字符串，靠 `' · '` 反解析（E15） | 结构化的「频次」选择器 |
| 后果 | 家长面对空表单流失；或写出格式错乱的规则 | — |

**关键结论**：引导与 `A2`/`A3`/`E15`（`dailyLimit` 结构化）**必须同批落地** ——
模板库需要"频次"是结构化字段才能填充，否则模板只能产出又一条 `'条件 · 每天 N 次'` 字符串，
把 E15 的缺陷复制到引导流程里。

## 2. 目标流程（新用户，目标 ≤ 90 秒走完）

```
① 欢迎页           "把约定变成看得见的成长"
                   [创建孩子的积分账本]  [我有邀请码]
                          │
② 建立家庭         输入孩子昵称 → 系统生成 childId
                          │
③ 选择学段          幼儿园 / 小学低年级 / 小学高年级 / 初中
                   （决定模板过滤：年龄适宜性）
                          │
④ 选关注点（多选）   作业专注 / 生活习惯 / 阅读 / 运动 / 情绪管理 / 家务
                   （决定模板排序，不硬过滤）
                          │
⑤ 选约定（★ 核心）   展示 6–12 条模板卡片，已按学段+关注点排序
                   每条卡片：标题 / 条件 / 频次 / 分值，可 [采纳] / 跳过
                   至少采纳 1 条才能继续（否则应用无内容可做）
                          │
⑥ 设家长 PIN       4–6 位，用于"切到家长模式"（见 02 §7）
                   [跳过]（可后续在设置里设）
                          │
⑦ 完成 → 首页       空账本 + 已采纳的习惯，提示"点一下卡片就能加分"
```

**每一步都可跳过吗**：③④⑤ 中，③④ 可跳过（默认学段=小学低年级、无关注点）；
**⑤ 不可跳过**（至少 1 条）—— 没有规则的产品对新用户毫无价值。
⑥ 可跳过，但跳过时家长模式的权限提升需每次输入 PIN（体验提示中说明）。

## 3. 数据模型

```prisma
model RuleTemplate {            // 模板库（平台级，不属任何 child）
  id          String  @id @default(cuid())
  slug        String  @unique
  title       String            // 例：'番茄钟写作业'
  condition   String            // 结构字段：'专注 25 分钟'（不再塞进 detail）
  dailyLimit  Int               // 结构字段：2
  points      Int               // 恒为正
  direction   RuleDirection     // reward | penalty
  icon        String
  color       String
  ageBand     AgeBand           // 幼儿园 | 小学低 | 小学高 | 初中
  focusAreas  String[] @default([])   // ['作业专注','生活习惯']
  isSystem    Boolean @default(true)
  sortWeight  Int     @default(0)
  status      RecordStatus @default(active)
}

model Child {
  // ... 既有字段
  ageBand      AgeBand?
  focusAreas   String[]     @default([])
  onboardedAt  DateTime?    // null = 未完成引导 → 前端强制进入引导
}
```

> ⚠️ **权威定义（2026-10-12 补记）**：模板与成员的真实字段**以 `backend/prisma/schema.prisma` 为准**
> （本节是设计草图）。schema 里的 `RuleTemplate` 另含 `createdAt` / `updatedAt` /
> `@@index([status, ageBand, sortWeight])`；草图中主键的 `@default(cuid())` 与
> `focusAreas` 的 `@default([])` 已一并补齐。

**`onboardedAt` 是引导的权威状态**：服务端持有，前端不缓存。
理由同 `02` §7 ——客户端状态可被篡改，若客户端说"已完成引导"而后端没有 child 记录，
会出现"有 UI 无数据"的破损态。

**采纳模板 = 复制而非引用**：`RuleTemplate` → `PointRule` + `PointRuleVersion v1`（见 `02` §5.3）。
采纳后即与模板脱钩，家长可自由修改，模板库更新**不影响**已采纳的规则 ——
否则平台改一条模板会静默改动所有家庭的规则，是绝对不能接受的行为。

## 4. WBS（原 8.5 人日 → **按 P2 修订为 7.0 人日**）

> **P2 决策（用户 2026-10-12）**：L6 内容角色**不到位**，以当前设计内容为模板开发，
> 不追求完善。因此 O1 从「90 条 / 2.0 人日」降为「**18 条 / 0.5 人日**」，合计 8.5 → **7.0**。
> （`05` §2.3 的「AI 辅助 ≈6.1 周」是按**原 8.5 人日口径**估的，故实际会略短；
> 此处**刻意不把它折进 6.1 周** —— 避免制造新的算术不一致。）

| 编号 | 任务 | 产出 | 人日 |
|---|---|---|---|
| **O1** | **模板库内容 + 数据** | **18 条**模板（6 关注点全覆盖，含 2 条扣分）；`RuleTemplate` 种子；`slug` 命名规范 | **0.5** |
| **O2** | **后端** | `RuleTemplate` 表 + 查询接口（按 `ageBand`/`focusAreas` 排序）；`POST /onboarding/complete`（原子写入 `Child.ageBand/focusAreas/onboardedAt` + 采纳的 `PointRule` + `PointRuleVersion`）；`AuditLog` 记录 | 2.5 |
| **O3** | **双端 UI** | 7 个屏幕（Taro + Flutter 各一套，共享文案与流程定义）；步骤状态机；至少 1 条约定的校验；PIN 设置 | 4.0 |
| | | **合计** | **7.0** |

**O3 为何是 4.0 人日**：双端各 2.0 —— 而双端一致性是本项目既有的强约束
（本批修复已建立"同一用例双端各跑一遍"的机制，O3 必须沿用）。

**O1 为何从 2.0 降为 0.5 人日**：18 条模板的**数据**已由工程侧在 W0 交付
（`backend/prisma/seed/templates.data.ts`），并带**离线自检** ——
图标名是否真实存在、配色是否在色板内、分值是否越界、slug 是否重复、
6 个关注点是否都有模板；**7 类坏数据 + 空分组全部可被拦下**（`npm run templates:check`）。

但请**明确认知这次降级的代价**：原「90 条」不是随手写的数量 —— 每一条要给出
**可判定的条件**（"专注 25 分钟"可判定；"好好学习"不可判定）、**合理的频次**、
**匹配的分值区间**（见下方分值规范），以及**按 4 学段做适宜性区分**。
这是**内容判断工作，不是工程工作**，**AI 编程无法压缩它** ——
AI 压缩的是编码，不是需要儿童教育判断的内容产出。→ 对应阻塞项
**L6「内容角色（规则模板撰稿人）」**，完整定义见 `05` §6（已按 P2 裁定解除）。

**18 条的具体代价**：当前 `primary_low` 学段模板较密集，
而 `preschool`（1 条）与 `junior_high`（0 条）覆盖很薄 ——
引导第⑤步对这两类家庭会显得单薄。**不影响功能正确性**，但计入 **R4（转化率）**。

### 分值规范（O1 的验收标准）

| 类型 | 示例 | 建议分值 |
|---|---|---|
| 日常小习惯（每天可做多次） | 按时起床、主动整理 | 1–2 |
| 日常任务（每天 1 次） | 自主阅读 20 分钟、自己收书包 | 2–3 |
| 需要持续投入 | 番茄钟写作业、练琴 30 分钟 | 3–5 |
| 周频次任务 | 围棋课后作业、大扫除 | 5–10 |
| 扣分约定 | 顶嘴、不按时睡觉 | −1 ~ −3 |

**约束**：单条模板 `points ≤ 10`（超出会让积分体系失去"积累感"）；
扣分模板必须 `direction = penalty` 且 **`addHabitFromRule` 会拒绝**（A1 已修）。

## 5. 同意与合规（与引导交织）

引导第 ① 页底部必须有：

```
继续即表示您已阅读并同意《用户协议》与《儿童个人信息保护规则》
[ ] 我是该儿童的监护人，并同意为其创建积分账本
```

- 勾选前 ①–⑦ 全部不可进行（`GuardianConsent` 记录 `grantedAt` / `version` / `ipHash`）
- 未勾选时，`onboarding/complete` 返回 `403 CONSENT_REQUIRED`
- 撤回同意（`02` §9.20）后，引导入口重新出现

**为什么放在引导而非设置页**：儿童个人信息的同意必须**在采集之前**取得，
而引导第 ② 步就开始采集昵称。放到设置页等于"先采集后征求"，合规上不成立。

## 6. 验收标准

| # | 用例 | 期望 |
|---|---|---|
| 4.1 | 新用户登录 | 进入引导，**不是**首页；账本为 0 分 0 记录（E18 落地） |
| 4.2 | 步骤 ⑤ 一条都不采纳 | 无法继续，提示"至少选一条约定" |
| 4.3 | 采纳 3 条模板 | 生成 3 条 `PointRule`，各自 `PointRuleVersion v1`；首页出现 3 个习惯 |
| 4.4 | 采纳后平台改模板 | 该家庭的规则**不变** |
| 4.5 | 采纳的扣分模板 | 生成 `direction=penalty` 规则；**不能**加入今日习惯（A1 一致） |
| 4.6 | 未勾选监护人同意 | `403 CONSENT_REQUIRED`，引导无法继续 |
| 4.7 | 未设 PIN 直接进入 | 允许；但切家长模式时每次都要输 PIN |
| 4.8 | `onboardedAt` 非空后重新登录 | 直接进首页，不重复引导 |
| 4.9 | 引导全流程耗时 | ≤ 90 秒（可用性测试，5 名家长） |
| 4.10 | 双端各走一遍 4.1–4.8 | 结论一致（R1 缓解） |
| 4.11 | 采纳模板产生的规则，其 `PointRuleVersion` 可被 `PointRecord` 引用 | I3 不变量成立 |
| 4.12 | 引导中途退出再进入 | 从上次步骤继续（`Child.ageBand/focusAreas` 已落库的部分不回滚） |
